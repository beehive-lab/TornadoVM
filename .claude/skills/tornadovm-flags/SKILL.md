# TornadoVM flags

Every flag is declared once, in the catalog classes of `tornado-api/src/main/java/uk/ac/manchester/tornado/api/options/`
(`RuntimeFlags`, `DebugFlags`, `ProfilerFlags`, `TaskFlags`, `OpenCLFlags`, `CudaFlags`, `MetalFlags`, `TcFlags`,
`LibraryFlags`). Everything else is generated from or checked against them:

- `tornado --list-flags` (add `--all` for internal flags): every flag with its type, default, and the value it is set to now. **Use this rather than recalling flag names**; it is always current.
- `docs/source/flags.rst`: the same tables, generated by `make flags-doc`, plus precedence and the removed flags.
- A unit test fails when the page is stale, when a doc, skill or launcher mentions a `-Dtornado.*` key that does not exist, or when code reads `System.getProperty("tornado.…")` directly.

## Setting flags

```bash
tornado --jvm="-Dtornado.print.kernel=true -Ds0.t0.device=1:0" -m tornado.examples/uk.ac.manchester.tornado.examples.VectorAddInt 64
tornado-test -V --jvm="-Dtornado.thread.info=true" uk.ac.manchester.tornado.unittests.foo.TestFoo
```

- **Write `--jvm="..."` with `=`.** `--jvm "-Dx=y"` with a single `-D` value makes argparse read it as an option and exit with code 2.
- Shortcuts in the `tornado` launcher: `--printKernel`, `--threadInfo`, `--debug`, `--fullDebug`, `--printBytecodes`, `--dumpBC DIR`, `--enableProfiler console|silent`, `--enableConcurrentDevices`, `--devices`.
- Precedence: `-D` (or `TornadoRuntimeProvider.setProperty` at run time), then the file named by `-Dtornado.options.file`, then `$TORNADOVM_HOME/etc/tornado.properties`, then the default. File entries are not copied into the JVM's system properties.
- Booleans take `true`/`false` in any case. Closed sets (`-Dtornado.cuda.sched`, `-Dtornado.tc.report`, `-Dtornado.enabled.backends`, ...) take only their listed words. A bad value stops start-up with the flag named.

### Per-task keys

`<graph>.<suffix>` or `<graph>.<task>.<suffix>`, where the names are those given to `new TaskGraph("s0")` and `.task("t0", ...)`:

| Key | Meaning |
|---|---|
| `-Ds0.t0.device=1:0` | backend 1, device 0 for task `t0` (`-Ds0.device=` for the whole graph). Backend indices: `tornado --devices`. |
| `-Ds0.t0.global.workgroup.size=1024,1024` | global work size per dimension |
| `-Ds0.t0.local.workgroup.size=16,16` | local work size per dimension |
| `-Ds0.t0.coarseness=2,2` | thread coarsening |

These keys are checked when the graph first compiles: a typo in the suffix or a task the graph does not have prints a warning, and a bad value fails.

### Set from Java

```java
TornadoRuntimeProvider.setProperty(DebugFlags.PRINT_KERNEL, true);           // checked now
TornadoRuntimeProvider.setProperty(TaskFlags.DEVICE, "s0.t0", "1:0");
```

Most flags are read once, the first time TornadoVM needs them. Setting one after that has no effect and prints `... already read it as X and keeps that value`. Set it on the command line, or before the first `TaskGraph`/`TornadoExecutionPlan`. The profiler flags, `-Dtornado.reuse.device.buffers`, `-Dtornado.deallocate.buffers` and `-Dtornado.experimental.partial.unroll` are re-read on every use.

## Recipes

| Goal | Flags |
|---|---|
| See the generated kernel | `-Dtornado.print.kernel=true`; to files: `-Dtornado.print.kernel.dir=DIR` |
| Launch sizes of each kernel | `-Dtornado.thread.info=true` |
| Runtime decisions, backend loading | `-Dtornado.debug=true`, `-Dtornado.debug.full=true` |
| TornadoVM bytecodes | `-Dtornado.print.bytecodes=true`, `-Dtornado.dump.bytecodes.dir=DIR` |
| Kernel and copy times | `-Dtornado.profiler=true`; keep instead of printing: `-Dtornado.log.profiler=true`; to a file: `-Dtornado.profiler.dump.dir=DIR` |
| Pick a device | `-Ds0.t0.device=B:D`, or for everything `-Dtornado.backend=B -Dtornado.device=D` |
| Load fewer backends (faster start-up) | `-Dtornado.enabled.backends=cuda` |
| Device heap | `-Dtornado.device.memory=8GB` |
| TC compiler IR | `-Dtornado.tc.dump=all -Dtornado.tc.dump.dir=DIR`; per stage: `-Dtornado.tc.dump=input,emit`; one function: `-Dtornado.tc.only=NAME` |
| TC HTML report of each compilation | `-Dtornado.tc.report=html` (written to `-Dtornado.tc.dump.dir`) |
| TC verbose / statistics / timings | `-Dtornado.tc.verbose=true`, `-Dtornado.tc.stats=true`, `-Dtornado.tc.compile.times=true` |
| Verify TC IR after every stage | `-Dtornado.tc.verify=each` |
| CUDA: line info for Nsight, fast math, reproducible | `-Dtornado.cuda.compile.profile=debug` / `fast` / `repro`; extra NVRTC options: `-Dtornado.cuda.compiler.flags=...` |
| OpenCL compiler options / generated source | `-Dtornado.opencl.compiler.flags=...`, `-Dtornado.opencl.source.dump=true` |
| Run without a GPU | `-Dtornado.virtual.device=true -Dtornado.device.desc=FILE.json` |

## Start-up warnings

| Message | Meaning and fix |
|---|---|
| `-Dx is not a TornadoVM option and is ignored. Did you mean -Dy?` | Typo, or a key the application itself reads: rename it, or list it in `-Dtornado.options.allow=key,prefix.` |
| `-Dx was removed and is ignored. <reason>` | Drop it; the reason says what replaced it (`flags.rst`, "Removed options"). |
| `-Dx is deprecated and will stop working in TornadoVM V; use -Dy instead.` | Rename it now. |
| `-Dy and its former name -Dx are both set, to different values` | Remove the old name. |
| `Invalid value 'v' for -Dx: expected T` | Fix the value; `tornado --list-flags` shows `T`. |
| `-Ds0.t0.x: x is not a per-task option` / `task graph s0 has no task t9` | Fix the suffix or the task name. |

## Adding, renaming or removing a flag

1. Declare a constant in the right catalog class with key (`tornado.lower.dotted.words`), default, description (a sentence, single backquotes for code), category; `.internal()` if developer-only; `.dynamic()` only if it must change while the program runs. For a fixed set of words use `Option.choice(...)` / `choiceList(...)`, never `Option.string`.
2. Read it with `XxxFlags.NAME.get()` (`find()` if it has no default). Never `System.getProperty("tornado.…")`.
3. Add the key and default to `OptionDefaultsTest`.
4. Rename: change the key, add `.deprecatedKey("old.key", NEXT_RELEASE)`. Remove: delete it, add `new RemovedOption("key", "reason")` to `RemovedFlags` (in `api.internal.options`). `DeprecationDeadlineTest` fails when the deadline release arrives: then delete the old key or entry.
5. Update any launcher (`tornado-assembly/src/bin`), doc or skill that names the flag, then `make flags-doc`.
6. `make test-nogpu` (tornado-api tests check all of the above).
