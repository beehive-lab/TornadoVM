Compile time

Findings

  • Kernel quality is at parity or better on most benchmarks. Where TC is faster, ncu shows why: fewer registers on the GEMMs (40 vs 92–94 per thread) and fewer instructions on the convolutions and mandelbrot.
  • nbody is the exception. Same grid and occupancy, but 1.82× the instructions: TC keeps the 3-trip k loops rolled, so the private float[3] arrays stay in local memory. Full unrolling of small constant-trip loops (optimisation O9) is implemented and being verified; 1/sqrt → rsqrt (O12) is next.
  • Bugs this comparison found, fixed: stencil and convolveimage ran on a single GPU thread (43× and ~22,600× slower) because loop bounds became constants only after TC recorded the launch grid (3425f6496); juliaset crashed TC's emitter with a StackOverflowError, which also showed that internal TC errors must fall back to Graal instead of ending the JVM (b4569302b).
  • juliaset is 9% slower under TC (3.94 vs 3.61 ms): the escape-time loop, being looked at with the nbody work.
  • addImage, blurFilter and renderTrack use image and vector types TC does not support yet; they fall back to Graal.
  • Compile time, warm (342 kernels, many per JVM): TC's median is 4.49 ms against Graal's 3.84 ms per kernel (1.2× over the 292 kernels both compiled; TC faster on 65). NVRTC is identical (18.2 ms median both): it compiles whatever source it is given, so the source TC emits costs no extra driver time.
  • Compile time, cold (one kernel per fresh JVM): TC takes 65–98 ms where Graal takes 45–67 ms on most benchmarks, because a fresh JVM also loads and warms up TC's own classes; on the two convolution kernels TC is faster (83 vs 105 ms, 91 vs 111 ms). Cold-start cost is tracked for the C7 compile-latency gate.

Method

  • SDK from mikepapadim/tornadovm-compiler branch compiler/main, JDK 21.0.2, CUDA 12.6, driver 610.57.04; device 1:0 only (OpenCL devices blacklisted); default benchmark sizes; serial Java skipped.
  • Graal: default path. TC: -Dtornado.compiler=tc, fallback on.
  • Kernel time: nsys profile -t cuda, cuda_gpu_kern_sum, median of the benchmark's main kernel. ncu: --launch-skip 5 --launch-count 1.
  • Compile time: -Dtornado.tc.compileTimes=true prints the profiler's TASK_COMPILE_GRAAL_TIME (Graal or TC) and TASK_COMPILE_DRIVER_TIME (NVRTC) per task; TornadoVM's on-disk CUDA binary cache is disabled (-Dtornado.cuda.codecache.enable=False) so NVRTC really runs. Cold = one benchmark per fresh JVM, median of 3; warm = the 342 kernels of the C5b unit-test families, many per JVM.
